The observation override in the earlier workspace run prevented the test's
default `/daw_web_ui` name from attaching to a frontend-owned live engine. The
test returns success when no engine exists, so its result is recorded as a
skip-equivalent rather than green coverage. AE-P0.2 must not preserve that
behavior: the test must start an engine on its assigned run segment or fail when
its required fixture is absent.

The operating brief formerly stated that `DAW_ENGINE_TEST_MODE=1` used no real
audio device; `AGENTS.md` has since been corrected. Test mode changes
plugin/test-track topology and skips callback start, while `openAudioDevice` is controlled by
`EngineArgs::noAudio`. The agent e2e harness passes neither `--no-audio` nor
fixed sample-rate/block-size flags, so its configuration is derived from the
machine's current default device. The first e2e attempt was therefore
resource-contaminated and configuration-dependent despite its unique
SHM/project names. Its 34/34 output is retained as an observation and explicitly
withdrawn. The later 34/34 run is accepted as an exclusive-resource baseline,
but not as evidence of device-independent semantics; that requires the
AE-P0.2 equivalence decision.

Every one of its 187,392 samples is zero. Terminal evidence records that the
normal-mode capture command and metric gate ran; the WAV alone proves only a
structurally valid all-zero file. A no-source expected-silence content assertion
therefore passes, but an all-zero fixture cannot positively prove that the
capture tap was live. Separately, the run recorded 185 device callbacks and
seven underrun callbacks among 183 callbacks with a track to play (worst
shortfall seven blocks), and printed `Failed to receive control header` during
shutdown. Realtime stability, positive capture liveness, and shutdown
cleanliness remain red or unproven rather than hiding behind the metric pass.

## Isolation discoveries affecting interpretation

- CTest registers 211 tests. A bare noncanonical `--test-dir` still substitutes
  the canonical build for 118 direct shell engine checks: 103 are immune to
  `DAW_BUILD_DIR`, 15 honor it but default to the canonical build, and 93 use a
  compiled binary, Cargo, or another entry point. Therefore an independently
  named CTest build directory does not imply independent artifacts.
- 103 scripts prefer `ui/target/debug/daw-cli` over release when debug exists.
  That debug binary was rebuilt before any baseline suite.
- The tracked `ui-web/node_modules` path is an absolute symlink into the
  frontend-owned worktree. Web dependency tests are not attributable to this
  checkout until AE-P0.1 removes it and creates a local ignored install.
- Existing scripts have shared plugin-cache, audio-device, evidence-directory,
  and runtime-resource behavior. A full sweep is therefore serialized against
  the frontend owner's active gate rather than overlapped.
- Engine `testMode` is not a resource-isolation mode. Any test that needs a
  device-independent engine must pass an explicit no-device configuration with
  fixed sample rate/block size and prove semantic equivalence for its scope.
- Current tests do not emit a machine-readable source/artifact provenance
  manifest. The hashes in this record are manually captured evidence, not an
  existing fail-closed product capability.
